## 2. 直接采用的工程策略

### 2.1 每条网使用新图

本轮 scheduler **不传入预建 `graph=`，不跨网复用图或边缓存**。

已知 v0.1.3 图仍持有可变 Scene/config/成本场引用。构图后修改原对象，再传入内容等于旧快照的新对象，可能通过复用检查却使用已改变的依赖。

本轮直接用新建图和独立输入副本隔离该问题，避免为缓存机制再开一轮前置重构：

- 每条网构建自己的 Scene/config 快照或深拷贝。
- 给 Router 的固定占用在该次搜索期间保持不变。
- 每次调用新建有限图。
- 第一版使用 ZeroCongestion，以真实长度为代价；不接入可变自定义成本场。
- 报告明确 warm graph 复用仍未纳入本轮保证，不能宣称已修复该公共分支。

### 2.2 搜索仍然原生三维

所有网都直接调用三维搜索，从初始状态具有 z 自由度。禁止二维先布线、再抬升或修补。

cost 仍是：

```text
path_length + nonnegative_congestion_penalty
```

v0.2 基线令 congestion penalty=0，固定占用作为 hard constraint。不要把拥塞惩罚当成可以支付的碰撞。

## 3. 第一阶段：先完成两通道闭环

先实现并跑通两条网，再扩展数量，不要先写大型调度框架。

建议最小模块：

```text

src/native3d/multinet/occupancy.py
src/native3d/multinet/sequential.py
src/native3d/validation/joint_validate.py
examples/run_multichannel_baseline.py
```

可以按现有结构调整文件名，不为了模块数量拆文件。

### 3.1 输入

每条 Net 至少包含：

```text
net_id
source_pose
target_pose
```

共同输入：chip、静态障碍、静态参考中心线、RouterConfig、有序 net 列表。

第一版按输入顺序 A→B。排序策略只增加明确的可选项，不做复杂优化。

### 3.2 占用发布流程

1. 在静态场景中用 native3D Router 搜索 A。
2. 验收 A 的返回路径。
3. A 通过后，冻结其全部实际直线和圆弧，发布到 Occupancy。
4. 为 B 创建新 Scene：静态参考中心线 + A 的全部已发布曲线。
5. B 直接从三维状态空间搜索，避让 A。
6. 最后独立验收两条路径的全部曲线组合。

规则：

- 不只发布节点、控制点、折线弦或 AABB；占用是完整实际曲线。
- 保存 net_id、segment_id、occupancy_revision 和几何内容。
- 失败/未认证路径不得发布占用。
- 无偷偷调整已发布路径、无隐式 rip-up、无二维抬升。
- B 失败时保留已合法完成的 A，明确记录部分成功。
- 不把静态参考中心线误当成某条待布网的路径。

## 4. 把验收接入主流程，不再开独立的自间距修复轮次

### 4.1 单网验收

检查实际返回路径的端口、C1、Rmin、边界、障碍和固定占用间距。

接入后验自间距检查；本轮不加入路径历史状态，不声称在自间距约束下搜索完备或全局最优。

自间距语义必须明确：

- 整条路径使用累计弧长 `P(s), s∈[0,L]`。
- 只豁免全局弧长近邻带 `|s-t| < ell_local`，而不是同段/相邻段的整个组合。
- `ell_local` 是显式几何策略，单位 μm，与采样步长、细分层数和段索引无关。
- 第一版可以明确配置 `ell_local=2*dmin`；这是基线的局部几何豁免政策，不是论文参数或光学安全距离。报告必须披露该政策及适用范围。
- 若采用由已认证曲率下界推导的其他政策，给出推导与适用域，不能用未经证明的公式冒充认证。
- 同一段自身、多圈回返、相邻段远处以及非相邻段都要覆盖。
- witness 的两个全局弧长必须处于检查域内；豁免带内的最近点不能被当作违规。
- 生产验收和独立 JSON 验收都要实际执行这项检查。

不要直接把现有 `path_self_spacing(exempt_adjacent=True)` 接到 verdict 后就声称完整实现；它依赖分段并漏掉同段自交。

后验失败或不能认证要有明确状态和原始候选证据，不能写成 search_exhausted，也不能伪称已找到另一条合法路线。

### 4.2 网间验收

对 A×B 的全部连续曲线对检查：line-line、line-arc、arc-line、arc-arc。

跨网没有自间距局部豁免。不同网不能因为段号相同、端口靠近或 net_id 规则而忽略冲突。

分别输出采样估计、保守下界、违规见证和认证状态。无法认证不能算 verified success。

### 4.3 成功统计

区分：

- 搜索找到候选的 routed_count。
- 通过全部已声明验收的 verified_count。
- 已发布占用的 committed_count。
- 各类搜索失败、输入非法、后验失败、未认证。

不要用 16 个候选路径代替 16 条合法路径。不能把部分成功写成 all_success。

## 5. 两通道最小验收案例

至少完成：

1. 两条互不干扰的直线，均通过。
2. A 阻断 B 的平面路径，B 通过三维搜索避让。
3. A 包含圆弧，B 的输入确实包含这条完整圆弧；验证圆弧占用生效。
4. B 在已发布占用下确实无解，结果为部分成功，A 不被修改。
5. 交换输入顺序，分别报告 A→B 与 B→A 的路径和结果，不要求两种顺序相同。

三维避让案例可从如下几何开始：

```text
chip：(0,0,-60) -> (600,300,120)
Rmin=50 μm，dmin=5 μm，边界余量2 μm
A：(300,2,0) -> (300,298,0)，切向+y
B：(60,150,0) -> (540,150,0)，切向+x
无额外障碍或人工 waypoint
```

A 发布后，B 的 z=0 可行切片被 A 的间距带隔开；B 应由原生三维动作绕过。可以为端口边界合法性调整新案例，但要记录输入，禁止算法识别案例坐标。

自间距最小回归：

- 同一 C1 直线拆分前后结论一致。
- 正常空间弯曲通过。
- 单段多圈与拆段后的同一曲线均检测到非局部回返。
- 实际自交/自接近失败，违规 witness 在允许检查域内。
- 原跨墙路径保持合法。

## 6. 两通道通过后，直接扩展 4 / 8 / 16

沿用同一个顺序 scheduler，不另写不同规模的算法。每次占用发布后，下一网使用新 Scene 和新图。

### 6.1 16 通道必达基线

先做具有明确可行解的三维跨墙基线，避免一开始用极拥堵随机案例判断模块正确性。

可使用：

```text
chip：(0,0,-60) -> (600,300,120)
wall：(290,-50,-70) -> (310,350,40)
Rmin=50 μm，dmin=5 μm，边界余量2 μm
net i source：(60, 60+10*i, 0)，切向+x
net i target：(540, 60+10*i, 0)，切向+x
i=0..15
```

这是新增多通道场景，不改写原单网核心案例。该场景开始时没有额外静态波导占用，随后逐条发布已经验收的路径。

要求：

- 2 / 4 / 8 / 16 使用该系列的前 N 条网，主流程完全相同。
- 16 条最终均通过所声明的单网、网间和自间距验收。
- 墙阻断端口平面，每条跨墙路线的 z 变化来自三维搜索。
- 不手工给路径、层高、中点或换层位置。
- 记录每网路径、搜索 trace、占用 revision 和真实耗时。

### 6.2 加一个较拥堵的压力案例

增加 4 或 8 条端口交换/交叉配对的确定性案例，报告顺序布线的成功率与失败原因。

允许部分失败；不为压力案例引入 rip-up、不假称顺序基线一定能完成所有连接。
压力案例要体现已有占用影响后续搜索，而非全部是独立平行直线。
