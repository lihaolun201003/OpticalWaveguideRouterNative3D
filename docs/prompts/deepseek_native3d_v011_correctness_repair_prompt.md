## 2. 修复 A：A* 生成目标邻居时立即返回

主要位置：

```text
src/native3d/search/astar.py:208–227
```

当前在候选生成循环内执行 `goal_test`，发现目标就直接返回。这个终止条件不保证最优，即使启发式为零也会返回错误结果。

### 必须建立的反例

使用真实 `astar_search` 接口，构造有限图，不使用量化键：

```text
S = (0, 0, 0)
A = (1, 0, 0)
G = (2, 0, 0)
direction 均为 +x

S -> G：cost = 100，先生成
S -> A：cost = 1
A -> G：cost = 1
```

边成本满足非负性及 `cost >= endpoint Euclidean distance`。直接边可理解为长度 2 加拥塞惩罚 98。

修复前，欧氏启发式和 `h=0` 均可返回 100；正确答案为 2。

### 修复要求

- 使用正确的 A* 终止条件：目标以最小优先级出堆后结束，或保留最佳目标并证明 OPEN 下界已不可能改善它。
- 处理陈旧堆项、重复状态、更优 g 和必要的重新打开。
- 保留源点即目标、目标位置容差、目标切向容差、非负拥塞代价和预算状态的语义。
- 不通过把启发式全部改成零来掩盖终止条件错误。
- 启发式保留有证明的三维距离下界，例如 `max(0, distance_to_target - eps_pos)`。
- 明确最优性成立所需的状态、图、成本和终止条件；不要声称连续空间全局最优。

### 验收

- 上述反例在欧氏启发式和 `h=0` 下都返回 cost=2。
- 改变邻居生成顺序不能改变最优代价。
- 增加更多有限图，对照独立 Dijkstra 实现或人工可计算答案。
- 不能只拿同一个错误的 A* 设置 `h=0` 作为独立参考。
- `budget_exhausted` 与真正的 OPEN 耗尽继续分开记录。

## 3. 修复 B：量化去重合并了后继不同的实际 pose

主要位置：

```text
src/native3d/search/state.py:65–74
src/native3d/search/astar.py:148–149, 168–172, 228–232
src/native3d/search/router.py:63–77
```

当前 key 将相近位置和方向量化合并，但后继动作、碰撞和终端连接仍由实际 pose 计算。同 key 并不意味着同一状态，单个最低 g 不能支配其余实际 pose。

### 必须建立的反例

```text
S = (0, 0, 0)
A = (10, 0, 0)
B = (10.4, 0, 0)
G = (20, 0, 0)
direction 均为 +x
position key resolution = 10 μm
direction key resolution = 15°

S -> A：cost = 10
S -> B：cost = 10.4
只有 B -> G：cost = 9.6
A 没有到 G 的后继
```

A/B 当前 key 相同。已观察到量化去重版本 `search_exhausted`，精确 pose key 成功，cost=20。

### 修复要求

为 v0.1.1 选择并解释一个安全方案：

1. 使用保留不同实际 pose 的精确状态标识，量化仅用于候选索引，不用于无证明的删除；或
2. 每个量化桶保留多个实际 pose，只有有证明的状态等价或支配关系才能剪枝；或
3. 建立真正固定的规范离散状态图，从规范状态生成一致后继，并证明连续动作、端点和约束仍合法。

优先选择可清楚验证的小规模方案，不需要追求 1024 通道性能。

- 不能仅缩小量化分辨率来宣称根治。
- 不能仅保留桶内最低 g。
- 不能只修改文档却保留默认路由器中的不安全剪枝。
- 可以保留明确标为近似的实验模式，但正确性验收必须使用安全模式。近似模式耗尽不得被解释为真实可达空间不可达。
- 精确浮点状态也不等于连续空间完备搜索；说明状态重复、浮点误差和预算带来的限制。
- 若将来加入依赖路径历史的自间距约束，必须重新评估状态与支配关系；本轮不要借此扩展多通道。

### 验收

- 上述反例在用于验收的安全模式中成功，cost=20。
- 增加同桶不同方向、同桶不同碰撞可行性的案例。
- 完整运行实际路由器，不能只修有限图适配器。
- README、源码注释和报告撤回原来的“当前量化键保证量化图连通性与最优性”说法，写明新实现的保证范围。

## 4. 修复 C：独立验证器把近似距离当成认证下界

主要位置：

```text
src/native3d/validation/validate.py:121–145
src/native3d/validation/validate.py:273–302
src/native3d/validation/validate.py:313–332
src/native3d/validation/validate.py:385–406
```

`seg_seg_distance` 使用有限采样和局部搜索，得到的是候选距离最小值，即真实最小距离的上界，不能直接作为认证下界。

旧核心证据出现：

```text
obstacle sampled minimum = 5.773917590493442 μm
claimed certified lower bound = 5.820272826928609 μm

spacing sampled minimum = 34.47256295007042 μm
claimed certified lower bound = 34.47991081642641 μm
```

下界高于采样得到的上界，数学关系错误。这不是增加采样密度就能解决的问题。

### 必须建立的反例

距离函数级：

```text
segment A: (0,0,0) -> (100,0,0)
segment B: (3.125,-75,0) -> (3.125,25,0)
真实距离 = 0
旧 seg_seg_distance 可返回 3.125
```

完整验证器级：

```text
被验证路径：(0,0,0) -> (100,0,0)
已有参考中心线：(0.390625,-75,0) -> (0.390625,25,0)
dmin = 0.3 μm
chip = [-200,200]^3
无障碍物
源/目标切向 = +x
```

两条线真实相交。旧完整验证器可输出：

```text
sampled spacing = 0.109375 μm < 0.3 μm
claimed lower bound = 0.390625 μm > 0.3 μm
verdict = pass
```

### 修复要求

- 直线段之间实现解析最近距离，覆盖相交、平行、共线、退化零长度和端点最小值。
- 直线段与 AABB 使用正确的交点和距离方法，覆盖从面内部穿过盒体的情况，不能只比较盒边和端点。
- 圆弧可以采用有证明的自适应细分与弦误差界；对线/弧及弧/弧分别计入所有近似误差。
- 若使用弦近似，下界必须由正确的弦距离减去相关曲线偏差与数值误差得到，不能由采样最小值直接冒充。
- 明确细分子弧的角度范围及误差公式适用条件。
- 存在任意可靠的采样违规证据时，必须判失败；不能被另一个错误的“下界”覆盖。
- 无法完成认证时返回明确的未认证状态或保守失败，禁止输出 `pass`。允许保守误拒绝，不允许假通过。
- 报告清楚区分采样估计、解析距离、保守下界和认证状态。
- 维持独立验证：从序列化 JSON 重建几何，不导入生产 geometry/search/constraints 来充当第二实现。

### 连续边界与 AABB 一并修复

旧边界值 `-0.222572...` 是保守构造中的负弦误差。它既不证明越界，也不能证明连续安全；旧 `pass` 主要依赖采样点没有越界。

- 使用圆弧每个坐标的解析极值，或真正有证明的保守区间包围，认证整段位于芯片边界内。
- 检查 `src/native3d/geometry/primitives.py:257–281`：当前 AABB 极值逻辑会加入错误的另一侧极值，包围盒保守但并非所声称的精确包围盒，可能误拒绝合法路线。
- 正、负扫角，跨角度周期和任意空间平面都需要测试。
- 增加“采样点全部在边界内，但两采样点之间的弧段越界”的反例；独立验证器必须发现。

### 验收

- 两个交叉线段反例必须得到距离 0（在明确数值容差内），完整验证器必须 fail。
- 增加盒面穿透、刚好相切、刚好合法/违规 spacing，以及连续边界反例。
- 对有独立精确答案的案例验证 `lower_bound <= true_distance <= sampled_minimum`，允许明确且很小的浮点容差。
- 无法认证的案例不得被统计为通过。
- 不通过修改 dmin、Rmin、障碍位置、芯片体积或容差来让旧案例通过。
